# Mock Dataset Generator

`buildInputRootFile.C` generates the toy Monte Carlo dataset (`mydataset.root`)
used by every example in this tutorial — `example/basic`, `example/extended`,
and `example/advanced` all read the same file.

---

## Generating the dataset

From the repository root:

```bash
root mockDatasetGen/buildInputRootFile.C
mv mydataset.root mockDatasetGen/mydataset.root
```

The macro writes `./mydataset.root` relative to wherever `root` was invoked
(the repository root, per the command above), so it needs to be moved into
`mockDatasetGen/` afterward — that's the one location every example config
reads it from. See the root [README.md](../README.md#building-the-input-files)
for the full build-and-verify instructions.

---

## What's in `mydataset.root`

One `TTree` named `events`, with one entry per simulated event (1,000,000 by
default — see [Generation parameters](#generation-parameters-you-can-change)
below).

| Branch | Type | Meaning |
|---|---|---|
| `enu` | `double` | Neutrino energy. Drawn from one of two `chisquared_pdf` shapes depending on `reaction` (see below). |
| `pmu` | `double` | Muon momentum. Derived from `enu` with a reaction-dependent random smearing/offset, clipped at 0. |
| `pp` | `double` | Proton momentum. An independent draw from the same shape function used for `enu` (for the matching reaction category), scaled by 0.1. |
| `reaction` | `int` | Interaction/reaction-mode category, 1–6. Drawn from a fixed discrete distribution hardcoded in the event loop (reaction 1 is most probable, at 60%). |
| `selection` | `int` | Detected/reconstructed selection (topology) category. Which set of probabilities is used depends on whether `reaction == 1` or not. `-1` means the event was not selected ("invisible") — every tutorial fitter config filters these out via `selectionCutFormula: "selection != -1"`. |
| `asimovWeight` | `double` | Per-event weight. Fixed at `0.05` for every single event — it's the `Event` struct's default initializer and is never modified anywhere in the generation loop, so it is a flat constant, not a computed value. |
| `par1_TGraph` | `TClonesArray` of `TGraph` (one graph per event) | Smooth, event-specific systematic response curve, 7 knots at x = -3,-2,-1,0,1,2,3 ("sigma" pulls, per the code's own comment), generated by `fillSmoothRandomResponse()`: a random per-event exponential of a linear+quadratic function of x, clipped to [0.05, 3.00], pinned to 1.0 at x=0 (nominal). Internal `TGraph` object name: `par1_response`. |
| `par2_TGraph` | `TClonesArray` of `TGraph` (one graph per event) | Same construction as `par1_TGraph` (independent random draw, same `fillSmoothRandomResponse()` shape). Internal `TGraph` object name: `par2_response`. |
| `par3_TGraph` | `TClonesArray` of `TGraph` (one graph per event) | Same 7-knot layout, but via `fillRandomResponse()` instead: every non-nominal knot gets an independent, uniformly random value in {0.00, 0.01, ..., 1.00} — deliberately **non-smooth**, unlike `par1`/`par2`. Knot at x=0 is still pinned to 1.0. This is the response used by `example/extended`'s E05–E07 to compare spline/graph interpolation methods. Internal `TGraph` object name: `par3_response`. |

## Generation parameters you can change

All at the top of `buildInputRootFile.C` unless noted:

- **Event count** — `int nEvents{int(1E6)};` (line 1). Default 1,000,000. Edit
  directly for a bigger or smaller dataset.
- **Random seed** — `gRandom = new TRandom3(202404);`, inside
  `buildInputRootFile()`. A fixed integer seed, so generation is reproducible
  run-to-run; change it for a different random draw. (The in-code comment
  calls this "a UUID" — it isn't; it's just a fixed integer.)
- **Number of response-function knots** — `constexpr int nKnots = 7;`
  (line 2). Not freely changeable on its own: the knot x-positions
  (`par_x[nKnots] = { -3, -2, -1, 0, 1, 2, 3 }`, inside `buildInputRootFile()`)
  are a hardcoded 7-element array, so `nKnots` and `par_x` need to be edited
  together.
- **Kinematic shapes / reaction mix** — `fShape1` (`chisquared_pdf(x, 4)`) and
  `fShape2` (`chisquared_pdf(x, 5)`) drive `enu`/`pp` for `reaction == 1`
  versus all other reactions, respectively. The `reaction` and `selection`
  probabilities themselves are hardcoded literal thresholds in the event
  loop (e.g. `if (buffer < 0.6) { e.reaction = 1; }`) — edit those directly
  to change the topology mix.
- **Output filename** — `TFile::Open("./mydataset.root", "RECREATE")`. Every
  example config in this tutorial expects the file at
  `mockDatasetGen/mydataset.root`, so if you rename the output here, update
  those paths too.
